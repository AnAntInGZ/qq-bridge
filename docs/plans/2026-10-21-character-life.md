# 生活决策与连续角色实现

日期：2026-10-21。承接离线调度，用户要求今天设计并实现两项：DSH 受限生活决策/预算作息/生产调度接入，以及心情/兴趣/记忆整理/删除更正。

## 设计决定

1. 新增 qq-life 独立预设，复用唯一工具守卫的严格 life 模式。只注册 character_propose 原生工具；隐藏全部继承工具并禁止本地执行、QQ 发送、联网和 MCP。工具仅向调用者自己的 DSH 会话追加结构化提案事件。桥接通过已有鉴权事件流的 sessionId 绑定轮次，不把控制台或轮次密钥交给模型，不新增可伪造 sessionId 的 HTTP 工具端点。
2. 每个决策尝试创建一次性会话，分别按范围提供快照；只处理实时事件，明确成功结束后才提交。取消、超时、断连、旧轮次和未知 preset 均拒绝提交；停止未确认时保留占用，既有 QQ 聊天独立运行。
3. character.autonomy 默认关闭，启用须明确预算时区、配置作息、日轮数及 token/费用上限；每次尝试先持久预留，失败和重试同样占用。未知用量保留预留；时钟回拨、重启和时区改变不重复发放额度。按配置间隔只产生一项到期事件，不补跑停机期间的空闲轮次。暂停始终本地优先。
4. SQLite v3 在事务内迁移，旧库先快照。心情采用愉快/激活/掌控与独立精力；状态变化必须引用当前范围依据，幅度受限且每个依据只生效一次。兴趣只从真实经历评价缓慢更新，按范围投影；随实际时间向基线衰减，不因重启回满。
5. 记忆保存来源引用与独立事实/感想，以范围交集约束检索与整理。更正/删除递增可见版本、使摘要和状态依据失效、撤销轮次、退役读过旧内容的 QQ 与生活上下文；删除同时清理重复正文及受托管备份，保留无正文的删除清单以阻止旧备份复活。无法确认旧上下文已停时阻止后续发送。不能承诺删除已经发送的 QQ 或模型服务保留的数据。

两项已完成代码交付，生产入口已接入，默认关闭且启动后暂停。保留工作区已有改动，在 main 上开发，未 commit、push 或改动真实运行配置。

### 已实现

- 新增 qq-life 生成预设、唯一守卫的 life 模式及严格的 character_propose 原生工具。按 DSH 0.2.1-rc.2 的公开工具契约构造定义，不从裸链接插件导入仓库外的内部包。每轮等待订阅快照确认后才投递；历史快照不作提案或完成回执。取消受理不能代替退出确认。
- 协调器接入主桥接、本地到期关注和真实近况来信；范围独立、一次性会话、单槽位、预算预留、作息、超时和重试共同准入。模型仅可提出不行动、感受和记忆整理；本批没有外部活动候选或执行器。
- SQLite v3 保存来源绑定的心情、精力、缓慢兴趣与记忆整理，固定本轮可见来源。来信事件与对应经历共用刺激标识，不重复计算；收到陈述只证明对方这样说。
- 管理员可按范围查询经历/记忆并更正、删除。变更清单、备份清理、记忆版本、旧 token 撤销、旧上下文停止和发送闸门组成恢复流程；失败不会回报已完成。删除保守重置全部已知 QQ 上下文与本地缓存。
- 补入真实竞态回归：删除与创建会话、离线补投失败、命令回执晚到均不能重投或发送旧正文。其中迟到失败重投与迟到命令发送均先复现失败，再修复通过。工具守卫另以实际 schema 填充默认 chat 配置复现并修复挂载兼容回归，保留本地工具拒绝断言。
