# DeepSeek 自主角色最终方案评审

日期：2026-10-19。本页保留评审的产品方向与方案取舍；owner 已要求开始开发，当前已交付基础存储、活动登记、近况投影、[离线调度与有限重试](2026-10-21-character-scheduler.md) 及 [受限生活决策与连续角色](2026-10-21-character-life.md)，见 [运行时指南](../guides/CHARACTER_RUNTIME.md) 和 [开发记录](2026-10-19-character-foundation.md)。完整目标见 [详细设计](../guides/AUTONOMOUS_CHARACTER.md)。

## 希望实现的体验

她通过 QQ 和你及群友交流，保留同一个角色的兴趣、心情和经历。没人找她时，她可以从允许的内容池挑视频、理解内容，或者在固定安卓模拟器里玩一款消消乐，也可以休息。你回来问近况，她能根据实际记录说清做了什么、做到哪里、有什么感想；重启后还能接续。

例如：她自主选择一个允许公开的视频，分析了其中一段，保存来源、覆盖范围和感想。你回来问，她可以说“刚分析了前两分钟，有个地方挺有意思”；没有实际播放记录就不声称完整看完。若在游戏中收到问话，她先回应近况，需要停下来时等当前交换结束、画面稳定后再暂停。

角色的连续性体现在选择、偏好和能核对的往事里。一个私聊中的内容不会因为“同一个角色”就出现在另一个群。

## 首版边界

保留 DeepSeek、DSH、QQ、人设、表情和现有图片及 Seed 视频能力。新内容为单角色协调、经历记忆、状态与兴趣、B 站内容适配、固定游戏技能，以及相应控制台与预算。

第一版限定一台运行主机、一个角色、一个模拟器实例、一款非计时消消乐和一个明确的 B 站内容池。B 站验收重点是自主选片、真实内容理解和有依据的交流；完整网页浏览与播放动作不列为必需。游戏先验证识别与操作闭环，允许输，不以必胜作为承诺。

## 建议采用的设计决定

下列是本次提交 review 的方案选择，不表示已经得到运行授权。

| 决定 | 最终方案 | 原因与代价 |
| --- | --- | --- |
| 角色与聊天 | 一个调度器统一活动；QQ 各会话继续独立交流 | 保证生活连续，同时保留现有模式与收发链路 |
| 模型分工 | DeepSeek 选择活动并交流；Seed 提供视频证据；基础求解器处理局内交换 | 控制延迟和费用，按能力核对结果 |
| 决策执行 | 模型只暂存意图，回合成功后由宿主校验、登记和执行 | 多一个提交边界，避免中断回合留下失控操作 |
| 唤醒与并发 | 事件和到期时间驱动；一个决策轮次、一个主要独处活动 | 空闲不持续轮询模型，活动可在安全点被打断 |
| 状态存储 | 单机 SQLite，宿主唯一写入；P0 优先验证 node:sqlite | 不增加数据库服务，最低 Node 与目标系统仍须验证 |
| 信息范围 | 不同范围隔离模型上下文；派生内容继承来源允许目标的交集 | 私聊、群聊、摘要和日记都遵循同一边界 |
| 视频共用 | 把实际上传与分析收口到宿主唯一媒体队列 | 需要同时改造 QQ MCP 接入，不能靠多个实例的 busy 标记 |
| 游戏能力 | 固定设备与游戏，截图识别、基础求解、单次操作、再观察 | 每个游戏版本都要校准，不做任意桌面或通用手游控制 |
| 故障恢复 | 先持久登记；未知点击与发送先核对，不自动重放 | 某些异常需要人工接管，优先保住记录真实性 |
| 启用与退回 | 分项开关默认关闭，先离线、再小样、最后有限额运行 | 可逐项验证，出现问题能停用新模块并保留 QQ 主链路 |

具体接口、状态迁移、租约、重试和费用处理见完整设计中的“决策如何接入现有 DSH”“状态和事件契约”“B 站活动”“预算与控制台”。

## 一项活动如何闭环

```mermaid
flowchart LR
  E[授权事件或空闲到期] --> C[过滤权限 预算和候选]
  C --> D[按范围隔离的 DeepSeek 决策]
  D --> V[回合完成后校验并登记]
  V --> A[B 站或游戏执行器]
  A --> O[实际观察和回执]
  O --> M[保存事实 感想和状态]
  M --> Q[目标 QQ 会话按可见范围回应]
```

程序负责权限、时间、预算、资源和完成判定；模型负责偏好、解释与交流。下载受理、ADB 命令成功、预计时间到达都不足以证明活动完成。一次活动失败也能成为真实经历，但必须保留失败和未确认部分。

分享由目标会话基于可见记录生成，继续经过当前白名单、会话绑定、内容审计和发送额度检查。主动分享默认没有目标；先做到“问起时答得真实”，再按你设定的对象与频率开启主动联系。

## 实施顺序与每段可见成果

| 阶段 | 完成后能 review 什么 | 主要通过条件 |
| --- | --- | --- |
| P0 可行性 | 环境基线、DSH 受限决策契约、SQLite 恢复、B 站和设备小样记录 | 小样能拿到真实内容或设备结果，缺口明确 |
| P1 活动骨架 | 假活动的开始、暂停、恢复和 QQ 近况投影 | 去重、单活动、旧回执与旧执行器隔离 |
| P2 连续角色 | 有来源的感受、兴趣、记忆和有限计划 | 跨重启连续，跨会话不泄露，删除使旧上下文失效 |
| P3 B 站闭环 | 无人发消息时自主选择并理解视频，回来能说清经过 | 记录覆盖范围，唯一分析队列，不把摘要当完整观看 |
| P4 游戏闭环 | 固定游戏中持续交换，确认胜败或安全停止 | 棋盘识别门槛、每步依据、断连与人工接管安全 |
| P5 综合验收 | 控制台、有限额的 24 小时演示、恢复记录 | 事实一致、作息和费用生效、停用后 QQ 正常 |

每阶段先离线夹具，再在对应授权范围内验证真实依赖。真实账号、Seed 调用与设备操作分别记录，mock 通过不能代替真实接入验收。阶段完成以完整设计的编号标准为准。

| 参数 | 建议起点 | 最晚确定时间 |
| --- | --- | --- |
| 运行主机、模拟器与游戏版本 | 先固定一种环境、一款非计时游戏及画面规格 | P0 设备小样前 |

| 角色初始偏好 | 少量兴趣种子、初始状态和可公开范围 | P2 校准前 |
| 主动分享对象和频率 | 初始为空，优先允许问起时回复 | P3 主动发送前 |

## 评审关注点与停止条件

优先 review 三件事：这种“自主选择、真实积累经历、回到 QQ 交流”的体验是否符合预期；B 站先做内容理解、游戏先固定一款的范围是否合适；DeepSeek 管高层选择、基础技能承担具体操作的分工是否接受。

技术验收中，私人内容跨会话泄露、虚构完成、未经当前授权的发送或操作、重启后重复动作、额度失效均为阻断项。内容拿不到、游戏无法稳定识别、最低 Node 环境存储不满足要求时，停在相应阶段处理，不通过放宽权限或伪造经历继续。

完整自主活动尚未交付；基础实现的代码与验证结果另见开发记录。真实配置和账号活动均未改变，模拟器和游戏尚未选定。
