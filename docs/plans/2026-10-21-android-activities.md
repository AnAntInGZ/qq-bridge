# 安卓活动实现与部署计划

日期：2026-10-21。用户要求实现手机 B 站和安卓游戏；首款确认为开源离线 2048。最初选择独立 Linux Redroid 节点，随后用户改为 Windows 本机启动模拟器，由原服务器远程操作。当前按 Windows 方向推进，未启动任何 Android。

## 实现与部署决定

- 原服务器保留 QQ、DSH、SQLite、调度和受限 ADB 客户端。Windows 主动发起 SSH 反向隧道，把服务器回环端口映射到本机指定实例，无需家庭公网 IP。建议 MuMu 独立实例 4 核/4GB、720×1280；实际兼容性待实例启动验证。标准 ADB 层也可连接其他模拟器和云手机。
- 原服务器约 2GB 内存且余量不足，因此不在其上运行 Android。另一个新 Linux 节点实测总内存约 1.6GB；先前已授权发出的依赖安装安全完成，留下 Docker/Compose/ADB，尚无容器、镜像、APK 或 Android 实例。改向 Windows 后已停止并禁用新安装的 Docker、socket、containerd 服务；保留软件包与官方 apt 源，没有卸载或清理其他内容。服务器地址和凭据不入库。
- Windows 本机实测 6 核 12 线程、32GB、硬件 VT 已开启、当时约 11GB 可用内存；常见目录、卸载记录和进程中未发现已有模拟器。已询问用户选择/提供实例路径，未自动安装软件。
- Android 配置绑定固定回环设备、android_id、包、版本、分辨率、范围与校准界面。准备任务绑定设备、App 版本和记忆版本；换设备不得核销旧设备的未知任务。确定性解析 launcher 并启动，不使用 monkey 随机事件。模型无 shell、坐标、任意包/设备能力。
- 2048 包为 com.uberspot.a2048：PNG/CRC/像素校验、棋盘校准建议、单步确定性求解和实际合法后继核对。不凭命令返回声称成功。
- B 站 tv.danmaku.bili 固定版本及八个 UI 资源编号；真实父子树绑定视频卡片，拒绝广告/付费/登录/弹窗。仅依据标题和实际增长的播放进度形成有限经历，不声称理解内容或完整看完。没有新增付费视觉模型、评论、关注、投币或支付。
- 一个设备、一个操作者；持久预算预留和触控前登记，未知操作不重放。暂停/删除/权限与作息变化阻断后续动作。force-stop 后排除同包子进程、清理临时 UI 文件才释放占用；失败维持故障等待核对。
- 默认关闭。接入真实 bridge 管理员 API、协调器、调度候选和记忆删除更正链路。截图/UI 仅进程内处理；设备端固定临时 UI 文件读取后删除，断连可能残留，恢复时再次清理。

## 2026-10-22 B 站界面校准实测（登录后）

用户已完成 B 站登录并进入推荐流。按 `android-policy.mjs` 要求的 8 个选择器逐项核对真实界面（9.16.1，1440×2560），确认**现有契约中有三项与真实 App 不成立**，不是参数没填对，是获取证据的假设本身不匹配：

| 选择器 | 实测结果 |
| --- | --- |
| `feedReady` | 可用：`tv.danmaku.bili:id/recycler_view`（GridView，全域唯一） |
| `feedTitle` | 可用：`tv.danmaku.bili:id/title` |
| `feedCard` | **不可用**：卡片是可点击 `ViewGroup`，`resource-id` 为空；同层唯一带 id 的祖先只有 `recycler_view`（所有卡片共用），无法定位单卡 |
| `playerReady` / `playerTitle` | 分两种播放器，`playerReady` 无稳定共用标记 |
| `position` / `duration` | **不可用**：横版走 `UnitedBizDetailsActivity`，播放器是自绘 SurfaceView，UI 树内没有时间文本；竖版走 `StoryVideoActivity`，时间只有 `story_ctrl_seekbar`（SeekBar，dump 不带进度值） |
| `playing` | **不可用**：没有"暂停/播放"文本或描述节点 |

补充事实：

- 推荐流首屏混排横版视频与**竖版视频**（story）。竖版卡片 `content-desc` 以"竖版视频"开头，但 `feedItems` 的 `prohibited` 只匹配 text 等于广告/推广/直播/付费/充电专属，**拦不住竖版**，会点进 story 播放器后必然失败。
- `dumpsys media_session` 能稳定读到 B 站会话：播放 `state=PLAYING(3)`、暂停 `state=PAUSED(2)`；但 `position` 恒为 0，**进度拿不到**。
- 截图帧差可作为"画面在推进"的客观证据，实测：播放中相隔 1 秒 **18.42%** 像素变化（阈值 24），暂停后 **0.00%**。两次截图各约 1.6MB，解码耗时需计入 8 秒观察预算。

结论：`playerState()` 依赖"播放进度数字"的设计在真实 B 站不可用。已按「媒体会话播放态与标题 + 帧差 + 墙钟」重构，`feedCard` 改为"标题的最近可点击祖先"语义，详见下节。

## 2026-10-22 校准完成与真机验证

针对上节三个断点改了实现，并修掉两个此前没暴露的平台兼容问题：

- **选片**：只接受 `content-desc` 首段为 `视频` 的横版卡片。真机卡片形态是 `视频,标题,播放量`，竖版是 `竖版视频,标题,...`，直播/会员购/广告各有前缀，用白名单比在子节点里找文本稳。广告位 `ad_banner_item_container` 因此自然落选。
- **卡片定位**：`feedCard` 允许配空字符串，此时取标题的最近可点击祖先；点击仍要过结构校验——区域不超过画布 30%，范围内只能有一个已校准标题，配了 `feedCard` 时还要求 id 一致。
- **播放证据**：改为三者互证——媒体会话 `state=PLAYING` + metadata 标题与点开的候选一致（`sameTitle` 容忍媒体会话截断，最短 10 字）+ 两次截图帧差 ≥ 0.2% + 墙钟达到 `watchSeconds`。删掉 `playerTitle`/`position`/`duration`/`playing` 四个选择器。
- **标题来源**：详情页 `resource-id=title` 实测是合集名（"合集 · 新投稿！"）、集数（"9.3 好朋友"）、UP 主名和推荐位标题，同页出现 4 个，**真正的视频标题只在 media_session 的 metadata 里**。position 实测恒为 200，不随播放增长，所以进度只能靠帧差。`tests` 里保留了"进度不可读"的负例。
- **平台兼容一**：`dumpsys window windows` 在 Android 15 上不再输出 `mCurrentFocus`（314 行里没有），焦点校验一直失败；改用全量 `dumpsys window`（约 38KB），新旧版本通用。
- **平台兼容二**：`uiautomator dump` 会写完文件后以 139（段错误）退出，产物其实完整。改为先删旧文件、容忍 139、再以 XML 完整性校验作唯一判据，避免把有效观察判成命令失败。

真机端到端（MuMu Android 15 / 1440×2560 / B 站 9.16.1，冷启动走完整流程）：

```
候选 1 条 → 点击 → state=PLAYING → 标题完全匹配 → 10 秒后仍 PLAYING、标题稳定 → 帧差 31.08%
结论：真实设备全链路成立
```

竖版视频被正确排除，首屏只筛出横版普通视频。测试 22/22 通过（新增帧差、媒体会话解析、标题相似度三组用例）。

## 验证记录

### 2026-10-22 浏览形态：从单条打卡改成连续浏览

目标是"像人一样消磨时间"，不是每次点开一条看固定 20 秒。改了三处：

- 参数：`maxVideos` 1～3 → 1～8，`scrolls` 0～3 → 0～6，新增 `deepWatchSeconds`（命中兴趣时的停留，取值 watchSeconds～300 秒，0 表示跟随 watchSeconds，旧配置无需迁移）。
- 循环：按标题命中 interests 的词数决定停留——两个词都命中看满 `deepWatchSeconds`、命中一个取两者中间值、完全没命中只看 `watchSeconds` 就划走。剩余预算不够一条完整观察时主动收尾，**预算耗尽按完成记录**；只有观察失败、标题不一致、播放中断或画面无变化才判失败。
- 滚动：实测推荐流首屏经常一条横版视频都没有（一屏 5 个可点容器里只有 2 条 content-desc 首段是「视频」，另有 1 条「竖版视频」、1 条「会员购」、1 条宣传图），所以"首屏为空"是常态而非异常。改成先等一次重载再滚动；滚动的前置条件从"必须还在推荐列表"放宽为"不在播放器"——列表重载期间 `recycler_view` 会短暂消失，用它会把手速正常的等加载误判成失败（真机上已复现过一次）。

真机验证（MuMu Android 15 / B 站 9.16.1，watchSeconds 8、deepWatchSeconds 12、maxVideos 3、scrolls 3、activitySeconds 180）：

```
首屏候选 0 → 滚动 1 次 3 条 → 滚动 2 次 5 条 → 连续看完 3 条
fact：连续看了 3 条、共 35 秒（11/12/12 秒）；全程 121 秒
```

121 秒里实际观看 35 秒，其余是滚动、等重载、抓帧和返回的开销。这个比例是 UI 自动化的真实成本，不能把"在站内 121 秒"当成观看时长记账。离线 24/24 通过，同步到服务器后同样 24/24。

### 已完成：Seed 内容理解接入与跨公网链路的稳定性

上一节列的两步都已落地，并在真机上跑通：

- **目录白名单扩展**：分析器只认两个固定来源（`source: 'attachment'` → `state/incoming-videos/`，`source: 'activity'` → `state/activity-clips/`），`source` 是枚举，不接受调用方传任意路径。活动片段不产生附件编号，也不受附件模式白名单约束。
- **录屏接入**：`device.record()` 用 `screenrecord --time-limit N --bit-rate 3000000` 录一段，落盘后交给 Seed，读完即删。录制时长计入这次停留，因此 `clipSeconds` 被约束为不超过 `watchSeconds`，否则"看了多久"这个事实会被录制本身撑大。
- **失败只降级**：Seed 失败、录屏失败、超时（45 秒封顶）都退回纯播放证据，理由写进 `android-clip-error`，不影响这次观看成立。

实测量级（MuMu Android 15 / B 站 9.16.1，1440×2560）：

```
一次 600 秒活动：连续看完 6 条、共 173 秒，无故障
开启 analyze 后，经历逐条带上画面内容，例如：
  《[杜比]iPhone Duo，新十年的起点》停留 47 秒
  （画面内容：数码产品，介绍 iPhone Duo 折叠屏产品特点；屏幕显示UP主「两颗皮蛋」…点赞数 9741。）
Seed 单次分析约 22 秒；观察 6.3 秒（不截图）/ 13.4 秒（截图）
```

跨公网隧道暴露的三个平台问题，都已修掉：

1. **截图必须走文件**：同样 1.5MB，`exec-out screencap` 实测 29 秒、`adb pull` 3.6 秒——瓶颈在流式回传的小包往返。观察改为落盘再拉取，并且只在判断"画面是否推进"时截图。
2. **`adb shell` 偶发 SIGBUS(135)**：只读命令和滚动由 `retryExit` 重试一次，点击和返回不重试。
3. **UI 文本里的坏码点**：uiautomator 会把控制字符和截断代理对也写成实体，原实现直接抛"安卓 UI 字符无效"让整次观察失败，现在替换成占位符。

另有两处行为修正：

- **点击复核不再全等比较节点**：列表会动态加载，`parent` 索引和坐标都会变，按整个节点 JSON 比对会把正常刷新误判成"画面不再匹配"。改为按标题复核，并允许在最新画面上重新定位目标。
- **已确认的观看不再被后续失败抹掉**：此前只有预算耗尽才保留结果，滚动失败会把整条经历作废。现在只要有已确认的观看就记完成，并注明提前结束的原因。

运维踩坑：密钥文件用 root 创建、服务却以 `qqbridge` 用户运行，`600` 权限把服务自己挡在外面（`EACCES`）。部署时必须先 `chown` 成服务用户。

## 开错门改为跳过（2026-10-22 收尾）

真机连刷几轮后暴露出最后一个行为缺陷：**一次"点开却不是那一条"就结束整场**。17:00 那次活动连看 4 条、120 秒后被 `B 站打开内容与推荐候选不匹配` 收尾，凭证里写着"活动提前结束"，而实际上一次都没点坏页面。真人遇到广告跳转或推荐漂移是退出来换一个，不是今天不刷了。

改法：

- 把"点开 → 确认播放 → 看完"整块包进 try，只有预算到点、准入失效、动作额度用完才让整场结束；其余都当"这一条没看成"。
- 跳过时先**结清已发出的那一步动作**再退列表。这里是真正的坑：`android_steps` 里留着 `sent` 状态会让下一次 `back` 注册直接撞上"安卓动作槽或额度不可用"，把"换一条"变成"整场结束"——第一版补丁就栽在这上面。
- 连续 3 条都错才收尾：那时多半是页面结构变了，再点只是白花动作额度。
- 叙述里如实写"另有 N 条点开后不是列表里的那一条"，被跳过的标题不再计入观看条数。

夹具新增 `misreport:[下标]` 模拟播放态回报错误标题。新增两条回归：跳过一条后继续看完剩下两条（3 次点击、2 次返回、叙述带跳过说明）；三条全错时按上限收尾且不编出"停留 N 秒"。安卓 32/32。
