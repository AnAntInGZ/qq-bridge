# QQ 视频自动接收

四种模式都支持自动接收视频，不需要点击 QQ 的“接收”。`closed-agent` 只接收 owner 私聊并提供本地路径；`chat`、`reserved`、`reserved2` 接收白名单私聊和群聊视频，只提供附件编号。内容问答可启用独立的 [Seed 视频分析工具](VIDEO_ANALYSIS.md)。

## 启用条件

1. `closed-agent` 中的发送者必须为 `ownerQQ`；其他模式的私聊或群聊必须通过配置的白名单和黑名单检查。
2. `video.enabled` 为 `true`，并通过原有消息处理规则。静默模式忽略的非 owner 消息、工具审批回复不会触发下载。
3. QQBridge 和 Harness 在同一台机器运行，`dsh.baseUrl` 的主机名为 `127.0.0.1`、`localhost` 或 `::1`。远程 Harness 不会收到本地附件路径。
4. SnowLuma 能提供公网下载地址。桥接不会复制网关给出的本地路径，也不会自动操作 QQ 界面。

支持 QQ 原生 `video` 消息，以及作为 `file` 发送的 `.mp4`、`.mov`、`.m4v`、`.webm`、`.mkv`、`.avi` 文件。桥接先使用消息里的 URL；原生视频缺少 URL 时请求 `get_msg` 并核对群归属；私聊文件使用 `get_private_file_url`（需要 `file_id` 和 `file_hash`），群文件使用 `get_group_file_url`。已有 URL 下载失败时最多刷新一次。SnowLuma 的 `get_file` 不是视频下载接口，此功能不调用它。

收到视频不等于理解内容。接收模块不解码；启用 Seed 工具并配置密钥后，agent 可按附件编号分析画面和内嵌音轨。工具失败时应说明原因，不凭文件名回答。仿真回复仍由原有唤醒、潜水和发送规则决定。

agent 正在等提问答案时，也可以直接发送视频，文件路径会随答案提交。工具审批仍须回复“通过”或“拒绝”；视频不会被当作审批决定，也不会在等待审批时触发下载。

## 配置

已有 `config.json` 不必补字段，省略 `video` 时使用以下默认值。修改后重启桥接。

```json
{
  "video": {
    "enabled": true,
    "maxBytes": 104857600,
    "maxFilesPerMessage": 3,
    "maxStoredBytes": 1073741824,
    "timeoutMs": 120000
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `enabled` | 自动接收开关，设为 `false` 关闭 |
| `maxBytes` | 单文件最多 100 MiB，同时检查声明大小和实际下载字节 |
| `maxFilesPerMessage` | 单条消息最多接收 3 个视频，超出的附件明确标记为未下载 |
| `maxStoredBytes` | 视频目录总量最多 1 GiB，容量不足时拒绝下载 |
| `timeoutMs` | 每次下载最多 120 秒，含连接和重定向；刷新后的重试有独立时限 |

数字字段必须是正整数。下载按到达顺序串行处理，最多容纳 10 条正在下载或等待的消息；队列满时提示稍后重发。Harness 暂时不可用时仍先下载，恢复后沿用现有消息队列补投文件路径。该队列只存在内存里，进程重启后不会自动补投。

## 文件保存与权限

文件保存在仓库的 `state/incoming-videos/`，文件名使用随机 UUID，避免同名覆盖和路径穿越。下载完成并通过容器标识检查后才交给 agent，失败会清理临时文件。目录和附件沿用 `state/` 的访问边界，不提交到 Git。

容量达到上限时需要管理员手动清理已处理的视频。桥接不会自动删旧文件，以免 agent 在后续对话中仍需要它。清理前确认没有正在处理或待补投的任务；中断进程留下的 `.part-*` 文件也计入总容量，可在停止桥接后清理。

聊天和仿真会话只收到随机附件编号，不收到本机路径。二代仿真的未读和历史消息通过 `videoHint` 保留编号，一代仿真的上下文也保留附件信息。附件登记在 `state/video-attachments/`，有效期一天；模式切换或白名单撤销后需重发。聊天 preset 只增加 `analyze_video` 专用工具，仍禁止本地文件读写和命令执行。

## 实机验收与故障定位

启动 QQ、SnowLuma、Harness 和桥接后，按下面步骤验证：

1. 在 `closed-agent` 模式下用 owner 私聊发送一个小 MP4，先不点击接收。确认 `state/incoming-videos/` 出现新文件，Harness 会话收到路径和大小。
2. 让 agent 用视频工具读取它，再检查内容分析是否正确。Windows 沙箱读取被拒时，用现有的工具审批流程授权读取该附件；不要放宽整个 `state/` 的 ACL。
3. 再把视频作为文件发送，确认也能接收。若报缺少 `file_id`、`file_hash` 或下载地址，检查 SnowLuma 版本和事件字段，重新发送附件。
4. 在三种聊天/仿真模式分别用白名单账号发送，确认附件编号进入消息而没有本机路径；用未授权账号或群发送，确认不新增本地视频。

下载失败会把原因作为附件信息交给 agent，例如超限、目录满、HTTP 错误或网关缺少地址。收到“保存失败”时检查目录权限和磁盘空间；HTTP 地址持续失败时检查 SnowLuma 是否能获取原文件，再重新发送。目录里有文件但 agent 无法读取时，检查 Harness 是否真的与桥接共用本机文件系统，以及所选 preset 的文件工具权限。

离线回归使用模拟 QQ 网关与 HTTP 响应，不发送真实 QQ 消息：

```bash
npm run test:video
```

该测试已加入 `npm run test:audit`。离线测试验证下载、落盘与会话投递逻辑；真实 QQ/SnowLuma 版本兼容性仍需按上面的步骤验收。
