# 自主角色基础运行时

当前实现是角色的基础存储与活动登记，已接入桥接的只读近况投递和管理员 API。它还不会调用 DeepSeek 自主决策、刷 B 站、分析模拟器录屏或操作游戏。完整目标见 [设计方案](AUTONOMOUS_CHARACTER.md)，实际进度见 [基础实现计划](../plans/2026-10-19-character-foundation.md)。

## 已实现范围

- SQLite 持久保存事件、决策批次、活动、操作回执和经历；相同来源事件重复投递不重复登记。
- 提案只暂存，成功结束且状态版本仍有效才提交；一个角色最多一个主要活动。
- 已领取操作在结果未知、暂停或重启时进入待核对，不再次领取，不以超时当作完成。
- 经历保存事实、感想、结果和观察引用，按公开、指定群、指定私聊或内部范围隔离。
- 普通聊天、队列、二代唤醒和离线补投在实际投递时追加可见近况；退役聊天不删角色经历。

范围由宿主登记。公开候选经私聊决策选中后，活动和经历仍属于该私聊。其他会话只得到无细节的占用状态，不能读取标题、发起人或私人感想。模型投影不包含路径、执行代次或管理状态。

## 配置和存储

配置模板默认关闭：

```json
{
  "character": {
    "enabled": false,
    "recentLimit": 3
  }
}
```

`recentLimit` 是每次投影的经历上限，允许 1～5。当前拒绝其他 character 字段，避免未实现的开关被误认为生效。

关闭时不加载 `node:sqlite`，也不创建角色目录。启用后，宿主创建 `state/character/character.sqlite` 及 SQLite 日志；DSH 不直接读取数据库。沿用 state 权限，不为测试或沙箱放宽 ACL，数据库及备份不入库。

每次启动先暂停。目录不安全、数据库损坏或版本不兼容、已有存活操作者时，只停用角色模块并记录固定诊断，原有 QQ 交流继续。Node 22.13.0 的 SQLite 实验性告警保留，本批已在该版本运行离线回归，其他系统仍须单独验收。

## 管理 API

使用现有回环控制台的令牌、Host、Origin 和正文限制；QQ agent 仍被默认拒绝，未扩大 agent 白名单。

| 请求 | 语义 |
| --- | --- |
| `GET /api/character/status` | 可用性、暂停状态、版本、当前活动、待处理事件数和经历数 |
| `POST /api/character/pause` | 仅接受 `{"paused":true}` 或 `{"paused":false}`；字段无效返回 400，未启用返回 409 |

`phase` 为 `foundation`，`capabilities.autonomousDecision`、`bilibili`、`game` 都为 false。解除基础暂停不会启动模型、网络或设备任务，因为没有接入执行器。当前也没有控制台图形按钮。

暂停撤销在途决策，将已领取操作改为待核对；再解除暂停也不会恢复旧操作的执行权。同代执行器已取得的真实完成回执可归档到原活动，旧进程代次则必须根据新观察核对。核对接口目前仅供可信宿主代码调用，没有向模型开放。

## 宿主接口和恢复

实现位于 [runtime.mjs](../../src/character/runtime.mjs) 和 [policy.mjs](../../src/character/policy.mjs)。正常链路为 `ingestEvent`、`beginRound`、`stageIntent`、`finishRound`、`claimOperation`、`recordReceipt`。领取操作只登记执行权，没有外部副作用。未来适配器必须在真实动作前核对 `mayExecute`、权限、现场观察和预算。

事件消费、活动与操作登记用短事务一起提交；回执和经历一起提交。完成回执必须带观察引用，未知结果不产生已完成经历。同一事件编号的范围或摘要不同会报冲突。

本批结束失败、关闭或中断的未提交批次，保留原事件和轮次记录，不自动重算。完整设计中的模型重试、事件驱动循环、心情演化、费用预留和作息尚未实现。

`backup(name)` 在数据库自己的 backups 目录创建一致快照，只接受受限的 `.sqlite` 名称，不覆盖文件，也不继承原进程执行权。恢复副本后先暂停并核对。本批没有生产恢复、删除或更正 API；记忆删除须连同 DSH 上下文失效和备份删除清单一起实现，不能只删一行。

## 离线验证

```sh
npm run test:character
npm run demo:character
npm run check
```

演示在系统临时目录运行假活动，不读取真实 config，不连接 DSH、QQ、Seed、B 站或模拟器，不产生模型费用。单元回归登记到 `scripts/check.mjs`，真实桥接代码的近况与权限回归登记到 `scripts/test-audit.mjs`。全量检查仍有原有失败，见 [开发指南](HARNESS.md)。

## 真实验证前的准备

使用者在真实链路验收前自行安装并启动 DeepSeek Harness 和 QQ/SnowLuma，准备限定 QQ 目标及配置。项目不自动安装、打包或启停 SnowLuma。模拟器、B 站 App 和游戏尚未选定，不影响离线基础开发；截图、声音采集、录屏、Seed 费用及设备操作分别验收。

尚未交付 DSH 生活预设与决策适配、自动调度、预算与作息、唯一媒体队列、B 站或模拟器适配、记忆删除更正、心情兴趣演化和连续运行验收。P0 和 P1 都还有未完成项目，不计为整阶段完成。
